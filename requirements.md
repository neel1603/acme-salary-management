# Requirements

## 1. Goal

ACME is a multi-country organization with 10,000 employees. Its HR team currently manages salary data in spreadsheets. This project replaces that with web-based software that lets the HR Manager manage employee and salary data directly, and get answers to questions about how the organization pays its people — without needing to build a pivot table by hand.

## 2. Persona & Access

Single persona: the **HR Manager**. One implicit role, no login, no permission tiers — every screen and endpoint is available to whoever has the URL. This matches a take-home scope where the org has exactly one kind of user to design for.

## 3. Scope & Features

### 3.1 Data foundation

- **Countries** (8, seeded): ISO country code, name, currency code, and a fixed FX rate to USD with an "as of" date.
- **Departments** (8, seeded): a flat lookup list.
- **Employees** (10,000, seeded): code, name, email, department, country, job title, job level (IC1–IC4 through VP), hire date, employment status (`Active` / `Terminated` / `On Leave`), salary in local currency, and salary precomputed in USD for cross-currency aggregation.
- **Salary history**: every salary change is recorded automatically as an old/new pair with a timestamp, so past salaries and hike % are always recoverable.
- Seeding is deterministic (fixed random seed) so the same 10,000 rows are produced every run.

### 3.2 Employee directory

- Paginated, server-sorted, server-filtered table of all 10,000 employees.
- Filters: department, country, employment status, hire-date range.
- Free-text search across name/email, debounced on the client.
- Create a new employee.
- Edit an existing employee's details, including salary (which writes a salary-history row) and country (which re-denominates the salary into the new country's currency).
- Deactivate an employee (soft status change, not a delete).
- View an employee's detail, including their full salary-change history with computed hike %.

### 3.3 Salary management

- Every employee's salary is tracked in both local currency (source of truth) and USD (for reporting), computed from the country's fixed FX rate.
- Every salary change goes through the same update path, so a history row is always written — there is no way to change a salary without it being recorded.
- Hike % between any two history entries is computed on read, not stored, so it can never drift from the underlying values.

### 3.4 Analytics dashboard

- KPI cards: headcount, total payroll, average salary, median salary — all in USD, all respecting the active filter set.
- Breakdown by department and breakdown by country, each shown as a chart of average salary (with headcount and total payroll available in the tooltip).
- A shared filter bar (department, country, employment status, hire-date range) drives the KPI cards and both breakdown charts together.

### 3.5 AI query assistant

- A natural-language query box on the dashboard: the HR Manager can ask questions like "average salary in Engineering for employees hired after 2022" in plain English.
- Answers are generated by an LLM (Google Gemini) that calls the same KPI/breakdown/employee-search functions the rest of the app uses — so every answer is grounded in a real query result, not a model guess.
- The tool calls made to answer a question are shown alongside the answer, so the HR Manager can see what data backed it.

## 4. Delivery

- Backend: Python/FastAPI service layer, seed script, and test suite.
- Frontend: React SPA covering the dashboard and employee directory described above.
- Deployed and reachable end-to-end (frontend, backend, and database all live), not just runnable locally.
